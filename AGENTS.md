# КОНТУР — правила разработки для Codex и AI-агентов

Это демонстрационный барбершоп (чистые HTML/CSS/JavaScript). Сохраняйте текущую тёмно-зелёную/угольную тему, медные акценты, аккуратную типографику и основной пользовательский путь: услуги → цена → запись. Не переписывайте проект на React ради одной детали.

## Скиллы и их приоритет
1. При создании или улучшении UI используйте подходы **UI UX Pro Max**: сначала дизайн-система, типографика, сетка, контраст, доступность и адаптивность. Официальный репозиторий: https://github.com/nextlevelbuilder/ui-ux-pro-max-skill. Для полноценной работы с его генератором дизайн-системы установите официальный CLI в среду Codex командой `npx ui-ux-pro-max-cli init --ai codex` и используйте установленный `.agents/skills/ui-ux-pro-max/SKILL.md`.
2. Для создания элементов используйте локальный скилл `.agents/skills/21st-ui-build/SKILL.md`; для ревью — `.agents/skills/21st-ui-review/SKILL.md`. Источник: https://github.com/21st-dev/skill. Расширенные возможности поиска/установки компонентов требуют настроенного 21st CLI/плагина Codex (https://github.com/21st-dev/codex-plugin).
3. Следуйте реальным проектным ограничениям, даже если примеры 21st.dev сделаны на React. Не добавляйте ненужные зависимости и не копируйте чужие сайты.
4. Для КАЖДОГО изменения UI: до изменения создавайте отдельную ветку `backup-before-<change>` от текущего main; не удаляйте резервные ветки без разрешения.
5. Проверяйте реальную мобильную и десктопную вёрстку, а не только наличие CSS. Проверяйте изображения, форму, ссылки, SVG-стрелки, переполнение, состояние фокуса и корректность выбора услуг.
6. Не допускайте повторных декоративных лозунгов, битых картинок и пустых секций. Кнопки должны быть визуально выровнены. Для иконок используйте SVG вместо символов, которые сдвигаются из-за базовой линии шрифта.
7. Сайт — демо: никакие оплаты или реальные бронирования не проводятся. Не представляйте это как рабочую платёжную систему.
8. После обновления CSS/JS изменяйте версию ресурсов в `index.html`, чтобы пользователи GitHub Pages не видели устаревший кеш. Перед завершением укажите конкретно, что проверено, а что нет.

## Порядок работы
Проверь текущую версию → запиши точные дефекты → создай backup-ветку → внеси минимальные изменения → проверь на телефоне и ПК → проверь работу кнопок → отчитайся по изменениям.
